# Room Temperature Logger

An Arduino Uno and DHT11-based room-temperature logging system. The Arduino reads temperature and streams Fahrenheit values over USB serial; a PowerShell script timestamps each received value and appends it to a local text log.

The project began as a practical experiment: collect room-environment measurements over time and inspect whether overnight temperature patterns are visible in the data. It is a small data-acquisition project combining embedded programming, serial communication, and computer-side logging.

> **Measurement note:** This system records room temperature only. The current Arduino sketch does not record humidity, even though the DHT11 supports it. The project does not establish why a person feels warm, and it is not a medical device.

## System overview

```text
DHT11 sensor
    │ temperature measurement
    ▼
Arduino Uno (digital data pin D2)
    │ USB serial, 9600 baud; one Fahrenheit reading per line
    ▼
PowerShell script
    │ adds computer-side timestamp
    ▼
room_temp_log.txt (local Desktop file)
```

## Hardware and software

- Arduino Uno
- DHT11 temperature and humidity sensor (temperature is currently used)
- USB cable and jumper wires
- Arduino IDE
- Adafruit-compatible `DHT.h` library
- Windows PowerShell and a USB serial port (the current script defaults to `COM6`)

## Wiring

For a **three-pin DHT11 module**, connect:

| DHT11 module | Arduino Uno |
| --- | --- |
| VCC / + | 5V |
| GND / - | GND |
| DATA / S | Digital pin 2 |

Pin labels and module layouts vary. If you have a **bare four-pin DHT11 sensor** rather than a breakout module, identify its pins from its datasheet and check whether an external pull-up resistor is required before powering it.

See [the wiring notes](docs/wiring.md).

## Run the logger

### 1. Upload the Arduino sketch

1. Install the DHT sensor library used by the sketch.
2. Open `arduino/temperature_logger.ino` in the Arduino IDE.
3. Select **Arduino Uno** and the correct serial port.
4. Upload the sketch.
5. Close Serial Monitor and any other program that may be using the same serial port before starting PowerShell.

The sketch reads temperature in Fahrenheit approximately every five seconds and prints valid readings as one number per line. Invalid readings are skipped.

### 2. Configure and run PowerShell

1. Open `powershell/temperature_logger.ps1` in a text editor.
2. Set `$portName` to the Arduino's actual port (for example, `COM6`) if it differs.
3. Confirm that the configured log path is where you want to save the data.
4. Run the script in PowerShell. Keep the terminal open while collecting readings.
5. Press **Ctrl+C** to stop the logging loop; the script's cleanup block closes the serial port.

The default output path is `$HOME\Desktop\room_temp_log.txt`. Each run adds a session-start marker, and readings are appended rather than replacing earlier data.

## Log format

Each valid line is recorded in this form:

```text
2026-10-16 22:00:05 -> 72.0 °F
```

This is an **illustrative example**, not a measurement from the project. The timestamp is generated by PowerShell when it receives the serial line; it is not a hardware timestamp from the sensor. The computer's clock and time zone therefore affect the recorded time.

## Current implementation

- **Sampling:** the Arduino waits five seconds in each loop before reading the sensor.
- **Units:** degrees Fahrenheit.
- **Serial settings:** 9600 baud, 8 data bits, no parity, one stop bit.
- **Persistence:** PowerShell appends timestamped readings to a local text file.
- **Invalid sensor reads:** the Arduino skips values that are not valid numbers.
- **Humidity:** not currently collected or logged.
- **Analysis:** no conclusions are claimed here; actual log data must be examined before identifying trends.

## Limitations and next steps

See [measurement limitations](docs/limitations.md). Potential next steps include testing the logger over a known period, checking for missing or irregular timestamps, logging humidity, exporting parsed readings to CSV, and plotting temperature over time. Any enhanced version should be clearly distinguished from the original implementation, and any results should be based on real collected data.

## Data and privacy

Raw logs can reveal routines and when a room is occupied. Logs are intended to stay local by default and are excluded from version control. Do not commit personal logs, machine-specific paths containing private information, or other sensitive data.
